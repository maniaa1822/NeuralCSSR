## 3. Theoretical Framework

### The Belief State Problem

When mixing generators, the observed bit sequence is no longer generated by a single epsilon machine. The predictive distribution depends on:

1. **Which generator** produced the current segment
2. **What state** that generator is in

This creates a hidden variable problem where the observer must maintain a **belief state**—a posterior distribution over $(G, S)$:

$$P(G_t, S_t | x_{1:t})$$

where $G \in \{\text{GM}, \text{7SH}\}$ is the generator and $S$ is its internal state.

### How Mixing Mode Affects Belief Dynamics

#### Union Mode
```
[────── Golden Mean (50k) ──────][────── Seven State (50k) ──────]
```

- Within each segment: process behaves like the pure machine
- Single discontinuity at the boundary
- Beliefs quickly collapse to certainty about $G$
- Model synchronizes easily due to long uninterrupted runs

#### Switch Mode
```
[GM][7SH][GM][7SH][GM][7SH]... (every 500 tokens)
```

- Frequent regime changes every 500 tokens
- Model must re-synchronize after each switch
- More time spent in "uncertain" belief states
- Higher loss due to synchronization overhead

## 4. Key Findings

### 4.1 Union Achieves Lower Loss

Union mode (0.5440 nats) outperforms switch mode (0.5528 nats) by ~0.009 nats because:
- Longer segments allow complete synchronization
- Less time spent in uncertain/pre-sync states
- Cleaner separation between regimes

### 4.2 State Count Converges After Merging

Despite different raw state counts (61 vs 56), both converge to ~10-11 states after merging. This suggests the underlying belief machine complexity is similar:

| Component | States |
|-----------|--------|
| Golden Mean | ~2 |
| Seven State Human | ~7 |
| Cross-machine uncertainty | ~1-2 |
| **Total** | **~10-11** |

### 4.3 Merging is Highly Efficient

| Mode | States Reduced | Loss Increase |
|------|----------------|---------------|
| Union | 61 → 10 (84%) | +0.0026 nats |
| Switch | 56 → 11 (80%) | −0.0014 nats |

The dramatic reduction with minimal loss impact confirms that CSSR over-splits due to:
- History-based representation (different histories → same belief)
- Pre-synchronization states near regime boundaries
- Finite data effects

### 4.4 Excess Loss Explained

Both modes show ~0.05 nats excess loss over the theoretical optimum. Sources:

1. **Synchronization overhead**: First few tokens after regime change carry uncertainty
2. **Model imperfection**: Neural network doesn't perfectly match true distributions
3. **CSSR artifacts**: State assignments based on length-8 histories, not true causal states

## 6. Why Transformers Learn Belief States

The neural model naturally learns belief states because:

1. **Sequential processing**: Left-to-right mirrors causal conditioning
2. **Prediction objective**: Must encode sufficient information for next-token prediction
3. **Emergent structure**: Posterior beliefs over latent state emerge implicitly

CSSR then *extracts* these beliefs by clustering histories with similar predictive distributions—the distributions reflect the model's internal belief state.

---

## 7. Cross-Machine State Ambiguity

Some histories are genuinely ambiguous between machines. For example, `10101010` could arise from:
- Golden Mean in state A (alternating pattern respecting `00` constraint)
- Seven State Human in a compatible state

The model learns a **belief distribution** over both interpretations, creating states with mixed `machine_distribution` in the output. This is observable in the state alignment data where some CSSR states map to multiple ground-truth machine states.

## 8. Post-CSSR State Merging Algorithm

After two-stage CSSR discovers states, we apply a **JS-divergence-based merging** step to consolidate over-split states. This is implemented in `cssr_discovery/merge_states.py`.

### 8.1 Why Merging is Needed

Two-stage CSSR tends to over-split because:
- It uses fixed-length histories (L=8), not true causal states
- Different histories can encode the same predictive belief
- Finite data creates spurious distinctions between similar distributions

### 8.2 The Merging Algorithm

#### Step 1: Extract State Emission Distributions

For each discovered state $s$, we compute the **emission distribution** $P(\cdot | s)$—the probability of the next token given that state.

This is obtained from the neural model's predictions on the representative histories for each state:

```python
# For each state, get next-token distribution from model
for state_idx, histories in enumerate(partition):
    context = representative_history[state_idx]
    distribution = model.predict_next_token(context)  # P(x_t | history)
```

#### Step 2: Pairwise JS Divergence

Compute the Jensen-Shannon divergence between all pairs of state emissions:

$$JS(P_i || P_j) = \frac{1}{2} KL(P_i || M) + \frac{1}{2} KL(P_j || M)$$

where $M = \frac{1}{2}(P_i + P_j)$ is the mixture distribution.

JS divergence is symmetric and bounded: $0 \leq JS \leq \ln(2)$ nats (or 1 bit).

#### Step 3: Union-Find Clustering

States are merged using a **union-find** data structure with a tolerance threshold:

```python
def union_find_merge(distributions, tolerance_bits):
    tolerance = tolerance_bits * log(2)  # Convert bits to nats
    
    for i in range(n_states):
        for j in range(i+1, n_states):
            js = js_divergence(distributions[i], distributions[j])
            if js <= tolerance:
                union(i, j)  # Merge states i and j
    
    return clusters
```

This creates **transitive clusters**: if state A merges with B, and B merges with C, then A, B, C all end up in the same cluster.

#### Step 4: Compute Merged Emissions

For each cluster, compute a **weighted average** emission distribution:

$$P_{\text{cluster}}(x) = \frac{\sum_{s \in \text{cluster}} w_s \cdot P_s(x)}{\sum_{s \in \text{cluster}} w_s}$$

where $w_s$ is the number of histories assigned to state $s$ (its "size").

#### Step 5: Reassign and Evaluate

Rebuild the suffix lookup table mapping histories to merged cluster IDs, then evaluate loss on the dataset using the merged emissions.

### 8.3 Tolerance Selection

The tolerance threshold controls granularity:

| Tolerance (bits) | Union States | Switch States | Effect |
|------------------|--------------|---------------|--------|
| 0.01 | 2 | — | Too aggressive, loses structure |
| 0.001 | 10 | 11 | Good balance |
| 0.0001 | ~30-40 | ~30-40 | Conservative, keeps some splits |

We used **0.001 bits** as the default, which corresponds to:
$$\text{tolerance} = 0.001 \times \ln(2) \approx 0.00069 \text{ nats}$$

This is very tight—states must have nearly identical emission distributions to merge.

### 8.4 Example: Union Dataset Merging

Before merging: **61 states**

After merging at 0.001 bits: **10 clusters**

```
Cluster 8:  120 histories (36 original states merged)
Cluster 37:  65 histories (7 states merged)  
Cluster 51:  32 histories (2 states merged)
Cluster 28:  12 histories (1 state, no merge)
Cluster 0:    7 histories (6 states merged)
```

The largest cluster (8) absorbed 36 original states that all had similar "mid-probability" emissions around P(1) ≈ 0.5. These correspond to ambiguous histories where both machines could plausibly be active.

- Different histories mapping to GM:B get slightly different predictions

This is actually **correct behavior**: the CSSR algorithm is faithfully representing what the neural model learned, not the ground truth. The model has learned an *approximation* of GM:B with slight uncertainty.

## 10. Beyond Classical CSSR: Why This Works

### 10.1 Classical CSSR Requirements

The original CSSR algorithm (Shalizi & Crutchfield, 2001) requires several conditions:

| Requirement | Classical CSSR | Our Setting |
|-------------|---------------|-------------|
| **Stationarity** | Process must be stationary | ❌ **Violated** - regime switches break stationarity |
| **Ergodicity** | Single recurrent component | ❌ **Violated** - two machines have different recurrent structures |
| **Sufficient data** | Need enough samples per suffix | ⚠️ Marginal for rare states |
| **Known L_max** | History length must be sufficient | ✓ We use L=8 |
| **Single generator** | One epsilon machine | ❌ **Violated** - mixture of two machines |

**Our setting violates 3 of 5 core assumptions**, yet the approach still recovers meaningful structure!

### 10.2 Why It Still Works: The Oracle Difference

Classical CSSR estimates conditional distributions from **empirical counts**:
$$\hat{P}(x_{t+1} | x_{t-L:t}) = \frac{\text{count}(x_{t-L:t}, x_{t+1})}{\text{count}(x_{t-L:t})}$$

Our approach uses a **neural oracle** instead:
$$P(x_{t+1} | x_{t-L:t}) = \text{Transformer}(x_{1:t})$$

This fundamentally changes what we're discovering:

| Classical CSSR | Neural CSSR |
|----------------|-------------|
| Discovers structure **in the data** | Discovers structure **in the model** |
| Fails if data is non-stationary | Works if model handles non-stationarity |
| Requires sufficient counts per history | Works with single occurrences |
| Finds true epsilon machine | Finds model's **belief machine** |

### 10.3 The Transformer Handles Non-Stationarity

The transformer was trained on the mixed data and learned to:
1. **Track context**: Use recent symbols to infer which regime is likely active
2. **Maintain uncertainty**: Output belief-weighted predictions when uncertain
3. **Adapt predictions**: Different outputs for same suffix in different contexts

When we query the transformer for $P(x_{t+1} | \text{history})$, it returns a **marginalized prediction** that accounts for regime uncertainty:

$$P_{\text{model}}(x_{t+1} | h) \approx \sum_g P(g | h) \cdot P(x_{t+1} | h, g)$$

where $g$ indexes the generator. This is exactly what a **belief state** should encode!

### 10.4 What We're Actually Recovering

Classical CSSR recovers the **epsilon machine** of the process.

Our neural approach recovers something different:

> **We recover the epsilon machine of the transformer's belief distribution over the mixed process.**

This is not the same as:
- The epsilon machine of Golden Mean
- The epsilon machine of Seven State Human  
- The "product" epsilon machine of both

It's a **new object**: the minimal predictive representation that the transformer learned.

### 10.5 When Non-Stationarity Helps

Counter-intuitively, the non-stationarity might actually **help** in some ways:

1. **Regime diversity**: The model sees both machines, learning features of each
2. **Boundary learning**: Transitions between regimes teach the model about structure
3. **Robustness**: Model can't overfit to one machine's quirks

In union mode (single boundary), the model learns:
- Deep in GM segment → predict like GM
- Deep in 7SH segment → predict like 7SH
- Near boundary → hedge predictions

### 10.6 The Key Insight: Causal States Are About Prediction

The fundamental theorem of epsilon machines states:

> Causal states are the **minimal sufficient statistics** for predicting the future given the past.

This definition doesn't require stationarity—it only requires that:
1. There exists a predictive distribution $P(\text{future} | \text{past})$
2. We can partition histories by equivalent futures

Our neural oracle provides (1), and CSSR clustering provides (2). The theoretical guarantees about **optimality** may not hold, but the **constructive procedure** still works.

### 10.7 Comparison: What Would Classical CSSR Find?

If we ran classical CSSR on the raw mixed data:

| Issue | Consequence |
|-------|-------------|
| Pooled statistics | Would average GM and 7SH emissions |
| False merging | States from different machines with similar emissions would merge |
| Spurious splitting | Rare histories might create singleton states |
| No regime awareness | Can't distinguish "same suffix, different regime" |

The result would be a **confused mess**—not the clean 10-state structure we found.

### 10.8 Theoretical Framing: Belief-State CSSR

We can formalize what we're doing as **Belief-State CSSR**:

**Definition**: Given a model $M$ trained on data from a (possibly non-stationary) process, Belief-State CSSR discovers the epsilon machine of the **induced predictive process**:
$$P_M(x_{t+1:t+k} | x_{1:t})$$

This is always well-defined, regardless of the underlying data's stationarity.

**Properties**:
1. **Model-dependent**: Different models → different discovered machines
2. **Always valid**: The procedure works for any model with a predictive distribution
3. **Approximates belief machine**: If the model is well-trained, the discovered structure approximates the true belief machine over latent states

### 10.10.1 Can We Identify "I Don't Know Which Machine" Belief States?

**Short answer: Not directly from CSSR output.**

Here's why:

1. **The model doesn't explicitly track machine identity.** It just predicts next tokens based on history patterns. There's no internal "which machine am I in?" variable.

2. **CSSR merges states by PREDICTIVE EQUIVALENCE.** When GM:A (P(0)=0.50) and 7SH:ba (P(0)=0.5625) have similar emissions, they merge. This isn't uncertainty—it's correct information-theoretic behavior.

3. **Boundary predictions look normal.** We checked model predictions at the regime boundary (position 50000):
   ```
   pos 49997: P(0) = 0.4546  (before switch)
   pos 50000: P(0) = 0.4546  (at switch)
   pos 50002: P(0) = 0.4852  (after switch)
   ```
   The model doesn't show special "uncertainty" at the switch—it just predicts based on local patterns.

### 10.10.2 What the Mixed Clusters Actually Mean

Cluster 8 contains 57% GM and 43% 7SH positions, but this does NOT mean the model is uncertain. It means:

> **These contexts are OBSERVATIONALLY INDISTINGUISHABLE.**

From the history pattern alone, you cannot tell whether GM:A or 7SH:ba generated it, because both produce similar next-token distributions. The model correctly identifies these as equivalent for prediction.

### 10.10.3 Two Types of "Uncertainty"

| Type | What It Means | How to Detect |
|------|---------------|---------------|
| **Predictive equivalence** | Different GT states have same P(next) | CSSR merges them (correct!) |
| **True belief uncertainty** | Model unsure which machine is active | Need to probe internal representations |

CSSR captures the first type, not the second.

### 10.10.4 How to Detect True Belief Uncertainty

To find states where the model truly encodes "I'm uncertain about the machine," you would need to:

1. **Probe the hidden representations** for machine identity (linear probe on activations)
2. **Check if emission is a convex combination** of pure machine emissions that don't match any single state
3. **Analyze cross-boundary histories** where the model has seen tokens from both regimes

Some clusters DO show evidence of being mixtures:
- **Cluster 29**: P(0)=0.064 ≈ 66% × GM:B(0.0) + 34% × 7SH:aaa(0.1875)
- This COULD be the model hedging between machines

But distinguishing "similar emissions" from "belief mixture" requires additional analysis beyond CSSR.

## 11. Probing the Model's Belief Space

### 11.1 Beyond CSSR: What Does the Model Actually Know?

CSSR clusters histories by **predictive equivalence**—states with similar P(next_token). But the model might encode additional information in its hidden representations. Specifically:

> Does the model maintain a separate belief about **which machine is active**?

### 11.2 Linear Probing for Machine Identity

We trained a logistic regression probe on the transformer's final-layer activations to predict machine identity:

**Setup:**
- Extract activations from final transformer layer (64-dimensional)
- Train on "clear cases" far from boundary (positions 8-10000 for GM, 90000-99990 for 7SH)
- Test on held-out positions from same regions

**Results:**
| Metric | Value |
|--------|-------|
| Training accuracy | 100% |
| Test accuracy | **94.1%** |

The model's hidden states encode machine identity with high reliability.

### 11.5 The Factorization Hypothesis

**Key finding**: The model's hidden state appears to encode a **factorized** representation:

$$h \approx (\pi_{\text{machine}}, s_{\text{predictive}})$$

Where:
- $\pi_{\text{machine}} \in [0,1]$ = belief about which machine is active
- $s_{\text{predictive}} \in S$ = predictive sufficient statistic for emissions

**Evidence for factorization:**

We checked if the model distinguishes machine identity **within** the same emission class:

| Emission Bin P(0) | GM Histories P(7SH) | 7SH Histories P(7SH) | Separation |
|-------------------|---------------------|----------------------|------------|
| ≈0.0 | 0.147 | 0.209 | 0.063 |
| ≈0.1 | 0.272 | 0.237 | -0.035 |
| ≈0.5 | 0.128 | 0.378 | **0.250** |
| ≈0.6 | 0.366 | 0.967 | **0.601** |

For distinctive emissions (P(0)≈0.6), the model strongly separates machine identity (separation = 0.601). For ambiguous emissions (P(0)≈0.0-0.1), the separation is weaker.

### 11.6 What CSSR Captures vs. What the Model Knows

| Aspect | CSSR Captures | Model Knows |
|--------|---------------|-------------|
| Next-token distribution | ✅ Fully | ✅ Fully |
| Which machine is active | ❌ Indirectly (via emission) | ✅ Explicitly (in hidden state) |
| Position in sequence | ❌ Not at all | ✅ Potentially |
| Uncertainty about machine | ❌ Merges equivalent states | ✅ Maintains belief distribution |

**Implication**: CSSR discovers the **predictive equivalence classes**, which is the correct minimal representation for next-token prediction. But the model internally maintains richer information that could support other tasks.

### 11.7 Connecting to Information Theory

The probe accuracy (94.1%) tells us that machine identity is **recoverable** from hidden states. The remaining 5.9% error comes from genuinely ambiguous histories.

If we denote:
- $H$ = hidden state
- $G$ = machine identity (GM or 7SH)
- $X$ = next token

Then:
- CSSR recovers $I(H; X)$ = predictive information
- Probe measures $I(H; G)$ = machine identity information

The model has learned to encode **both**, but only the first is needed for the training objective.

### 11.8 PCA Analysis: Orthogonal Subspaces

Applying PCA to the hidden representations reveals the structure:

**Variance explained by top 5 PCs:** 63%, 21%, 7%, 6%, 1% (cumulative: 98%)

**Correlations with ground truth:**

| PC | Correlation with Machine Identity | Correlation with Emission |
|----|-----------------------------------|---------------------------|
| PC1 | +0.306 | -0.398 |
| PC2 | **-0.741** | -0.626 |
| PC3 | -0.082 | **+0.579** |
| PC4 | +0.254 | -0.060 |
| PC5 | +0.189 | +0.120 |

**Key observations:**
- **PC2** is strongly correlated with machine identity (r = -0.741)
- **PC3** captures emission information orthogonal to machine identity
- The top 2 PCs capture 85% of variance and encode both types of information

### 11.9 Quantifying Factorization

Training separate linear probes for machine identity and emission:

| Probe Target | Accuracy |
|--------------|----------|
| Machine identity | 93.7% |
| Emission (P(0) > 0.5) | 98.4% |

**Cosine similarity between probe weight vectors: 0.355**

This indicates **partial factorization**:
- The probes don't use completely independent directions (not orthogonal)
- But they're not fully aligned either (some separation exists)
- Machine identity is **partially recoverable** from the same representations used for emission prediction

## 12. Conclusions

1. **Mixing mode matters**: Union provides cleaner extraction; switch introduces synchronization noise

2. **Belief machine recovery works**: After merging, we recover ~10-11 states matching the theoretical joint machine complexity

3. **Neural CSSR validates the belief-state hypothesis**: The transformer learns approximate belief states as an emergent property of next-token prediction

4. **The model knows more than CSSR reveals**: Hidden representations encode machine identity (94% probe accuracy) even when CSSR correctly merges predictively-equivalent states

5. **Factorized representations**: The model appears to maintain separate dimensions for machine identity and predictive state

6. **Practical guidance**:
   - Use L_max ≥ 8 for complex mixed processes
   - Apply post-hoc JS merging to consolidate over-split states
   - Expect ~0.05 nats excess loss over theoretical optimum
   - Probe hidden representations to understand full model knowledge
